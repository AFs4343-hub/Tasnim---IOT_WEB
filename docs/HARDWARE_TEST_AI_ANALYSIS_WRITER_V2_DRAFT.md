# TASNIM — AI V2 Analysis Persistence Candidate

Status: **DRAFT — OFFLINE / EMULATOR ONLY, NEVER DEPLOYED**

## Canonical analysis paths

- `/hardware_test/history/<slot_ms>/analysis`
- `/hardware_test/analysis/latest`

The prototype predictions are generated by `ai/hardware_test_preview_v2.py` from validated, complete N0/N1/N2 V2 slots. The first valid slot is a temporal feature warmup, not an analyzed target.

## New code

- `ai/hardware_test_analysis_writer_v2.py` prepares a canonical, Firebase-RTDB-compatible record with explicit `model_version` and stable `inference_timestamp_ms`.
- Empty collections and null optional values are removed before writing (RTDB does not faithfully store empty arrays). The input object is not mutated.
- The code requires `data_source=HARDWARE_TEST`, `model_stage=PROTOTYPE_SIMULATION`, `time_mode=ACTUAL_TIMESTAMP`, a canonical 5-minute slot, and model metadata.
- History analysis is immutable: a different record in the same slot raises an explicit conflict, **including a different model version**. Do not silently replace it.
- `analysis/latest` advances only if the candidate has a later source slot. Out-of-order replays cannot rewind it.
- History and latest use **separate database transactions**, not one atomic operation. A crash between them requires retry of the **identical canonical record**, preserving the inference timestamp. Do not rerun a stochastic model or regenerate timestamps during an identical retry.
- Tests use both an in-memory transactional fake and an isolated RTDB emulator.

## Conditions not yet guaranteed

1. **Source snapshot integrity:** The writer itself does not authenticate a backend or re-fetch and lock the underlying N0/N1/N2 sensor history. A trusted caller must validate and authorize it first, and a final production pipeline must defend against source mutation after inference.
2. **Versioning/reanalysis:** Existing `ai.hardware_test_history_v2.prepare_backlog` treats any dictionary `analysis` as completed; replacing an old model version requires an explicit migration/versioning policy. Current writer rejects a different result for an occupied slot.
3. **Session boundaries:** A caller supplies `session_id`; do not blend separate field sessions into one temporal model context.
4. **Scientific interpretation:** RF/IF disagreement is marked `MODEL_REVIEW_REQUIRED`; it does not invalidate the model automatically or prove that the anomaly is real. All results retain `PROTOTYPE_SIMULATION`.
5. **Production operations:** No device login/gateway, authorization, production Firebase initialization, scheduled worker, model deployment, website authentication or measured-field accuracy evidence is provided by this candidate.
